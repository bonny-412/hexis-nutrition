> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Adattamento obbligatorio di questo progetto:** nessun `git commit`, mai (regola di Andrea). Dove la skill prevede un commit, fare solo `git add` dei file toccati dal task. Nessun test nuovo (vedi Global Constraints): le verifiche sono la suite esistente, `vue-tsc` e la checklist manuale.

**Goal:** Aggiungere l'agenda del professionista (viste Mese/Settimana/Giorno, visite in studio, videoconsulti, promemoria, blocchi di fascia oraria) e collegarla a "Prossima visita", all'archiviazione dei pazienti e alla data di fine del nuovo piano.

**Architecture:** Nuovo modulo backend `agenda` (entità `Appuntamento` unica per i quattro tipi, API `/agenda`, controllo sovrapposizioni con conferma esplicita) più piccole estensioni di `pazienti` (prossima visita, archiviazione, conclusione dell'appuntamento al salvataggio di una visita registrata). Frontend: pagina `/agenda` costruita a mano con Tailwind (nessuna libreria di calendario), con funzioni pure per date, festività e impaginazione degli eventi sovrapposti.

**Tech Stack:** Spring Boot 3.3 / Java 21 / Flyway / PostgreSQL; Vue 3 + TypeScript + Tailwind 4 + shadcn-vue + reka-ui + `@lucide/vue`.

**Spec:** `docs/superpowers/specs/2026-11-10-agenda-design.md` (leggerla prima di iniziare: è la fonte delle regole di comportamento).

Salvare una visita registrata con `appuntamentoId` non valido (inesistente, di un altro professionista, di un altro paziente, già `CONCLUSA`/`ANNULLATA`, non di tipo visita) deve fallire **senza** creare la visita; eliminare poi la visita registrata lascia l'appuntamento `CONCLUSA` con `visitaId` nullo. → Task 5.

- `aggiorna`: la famiglia di tipo non può cambiare (visita↔promemoria↔blocco); si può passare tra `VISITA_STUDIO` e `VIDEOCONSULTO`; una visita deve essere `PROGRAMMATA` (le `CONCLUSA`/`ANNULLATA` sono immutabili). `annulla`: solo visite `PROGRAMMATA`. `impostaFatto`: solo `PROMEMORIA`. `elimina`: solo `PROMEMORIA` e `BLOCCO` (le visite si annullano, non si eliminano).

### Task 3: Avviso di sovrapposizione con conferma

**Files:**
- Create: `agenda/SovrapposizioneException.java`
- Modify: `agenda/AgendaService.java`, `agenda/AgendaController.java`

**Interfaces — Consumes:** Task 2. **Produces:** `class SovrapposizioneException extends RuntimeException { List<AppuntamentoResponse> getConflitti() }`; nel `AgendaController` un `@ExceptionHandler(SovrapposizioneException.class)` che risponde **409** con body JSON `{"conflitti": [AppuntamentoResponse, ...]}` (un `@ResponseStatus` non basta: serve il corpo).

**Regola:** quando si **crea o si sposta/modifica una visita** (`isVisita()`) e `confermaSovrapposizione` è falso, si cercano (`findAllByProfessionistaIdAndData`) gli appuntamenti dello stesso giorno che sono `VISITA_*` con stato `PROGRAMMATA` o `CONCLUSA`, oppure `BLOCCO`, e il cui intervallo si sovrappone a quello della visita; se ce n'è almeno uno → `SovrapposizioneException`. Con `confermaSovrapposizione = true` si salva comunque. Intervalli **semiaperti** `[inizio, fine)`: finire alle 10:00 e iniziare alle 10:00 non è sovrapposizione. Si **esclude l'id** dell'appuntamento che si sta modificando. Le `ANNULLATA` non contano. Creare o spostare un `BLOCCO` o un promemoria non fa alcun controllo (scelta del piano: i blocchi li decide il professionista).

- [ ] **Step 1: Implementare** `SovrapposizioneException`, il controllo in `crea`/`aggiorna` e l'`@ExceptionHandler`.
- [ ] **Step 2: Verifica di lettura** (Review Focus 1): adiacenza = nessun conflitto; esclusione dell'id; `ANNULLATA` ignorata; con conferma si salva.
- [ ] **Step 3: `mvn test`** → BUILD SUCCESS. **Step 4: `git add`.**
